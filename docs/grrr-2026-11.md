# Google's November 2026 release (GRRR, `distributed_model_2026_11`)

What the release contains, what we verified on 4 November 2026, and what remains a
question for Google. Source for the dataset description: Google's reading notebook for
the release (a Colab shared with the team). Everything under "Verified" was read
directly from the bucket with `scripts/grrr_2026_11.py` and `scripts/check_grrr_coverage.py`.

## What it is

A new model: "an AI-based semi-distributed model operating on the HydroBasins river
graph", described by Google as an improved version of the model in Nearing et al.,
Nature 2024. Output is daily mean discharge at the outlet of every HydroBasins sub-basin,
draining the whole upstream area. Licence CC-BY-4.0, anonymous read.

| | Old bucket (`model_id_8583a5c2_v0`) | This release |
|---|---|---|
| Model | per-gauge LSTM, Nature 2024 | semi-distributed, HydroBasins river graph |
| Keyed by | Flood Hub gauge id | HydroBasins sub-basin (`subhybas_<id>`) |
| Locations | 1,031,646 | 970,005 with predictions; 1,034,083 outlets listed |
| Reanalysis | 1980-01-01 to 2023-12-23 | 1980-12-31 to 2025-12-30 (16,436 days) |
| Reforecast | issues 2016-01-01 to 2023-06-30, leads 0 to 7 d | issues 2016-01-01 to 2025-12-31 (3,653), leads 0 to 10 d |
| Thresholds | none shipped | return periods 1.01, 2, 5, 10, 20, 25, 50, 100 years, from the reanalysis |
| Inputs (per Google) | ERA5-Land, IMERG, CPC; HRES for forecast days (paper) | CPC + IMERG precipitation to issue time; HRES + GraphCast forecasts (notebook) |

The code comments in Google's notebook still say "1980-2023" and "2016-2023"; those are
leftovers from the previous notebook. The dataset headers give the dates above.

## Labelling and the lead-0 identity

Reanalysis time T covers the day [T, T+1d]. Reforecast lead L at issue T covers
[T+L-1d, T+L]. So the lead-0 value issued on day T+1 is the reanalysis for day T:

    Reanalysis[time=T] == Reforecast[issue_time=T+1d, lead_time=0]

**Verified** at `subhybas_1121902040` (Nigeria, a large river): equal to the float on all
3,653 issue days. Consequences:

- Lead 0 is not a forecast. A "reforecast matches reanalysis" check at lead 0 is true by
  construction and tells us nothing.
- The real consistency check is lead 1 to 10 against the reanalysis on the same valid
  day, per basin, at the leads each framework triggers on. That is the Somalia method
  (rank correlation and ratio by lead) generalised, and it is the first analysis task.
- The reforecast at issue T uses every input available up to T and "ignores the realistic
  delay of several hours" of an operational setting (Google's words). It is therefore
  slightly optimistic relative to a live forecast issued the same day.

## Coverage in the CERF countries

**Verified, basins.** Every outlet was joined to a Natural Earth 50m country polygon.
In all 28 CERF framework countries in the knowledge-base catalogue, every basin has a
prediction (one exception: a single coastal basin in Fiji). The 64,078 basins without
predictions are in Canada (33,692), Greenland (16,553), the United States (10,232,
Alaska) and Russia (982); 18,887 outlets fall in no polygon (coast, lakes), of which
16,269 have predictions.

**Verified, values.** 36 chunks of 128 basins (4,608 basins), 3 per country for the 12
countries above: zero NaN in both stores, zero all-NaN basins. The return-period table has
no missing values for any of the 970,005 basins.

**Not verified, and the actual coverage question.** A basin existing says nothing about
whether the model is any good at the framework's trigger station. "Coverage" for the
benchmark therefore means two further things, both open:

1. Which sub-basin outlet corresponds to each trigger station (SWALIM gauges, DHM Chatara
   and Chisapani, GRDC Niamey, FFWC Bahadurabad, N'Djamena, the Benue gauges). The outlet
   file is labelled UNOFFICIAL and picks one arbitrary outlet for coastal basins. The old
   bucket and the live API are Flood Hub gauge-keyed, so the team's Somalia and Nigeria
   work needs a gauge-to-basin mapping before it can be re-run on this release.
2. Whether Flood Hub publishes a live forecast there. The dataset is global; the live
   product is not. Which of the two defines "Google coverage" for the benchmark is a
   team decision.

## Questions for Google

- Which model is running live in Flood Hub and the API today: this release, the frozen
  2023 id, or a third? Our daily API snapshots for Somalia and Nigeria since 2025 come from
  whichever it is.
- Is ERA5-Land still an input? The notebook lists CPC, IMERG, HRES and GraphCast only. The
  stock-take's claim that GRRR shares ERA5 as an upstream with GloFAS and GEOGloWS came
  from the 2024 paper about the previous model.
- Is there a gauge-id to `subhybas` mapping for the gauges Flood Hub publishes?
- Will the reforecast be extended each year, or is 2025-12-31 the end of this release?

## Reproducing

```bash
uv sync
uv run scripts/grrr_2026_11.py subhybas_1121902040
uv run scripts/check_grrr_coverage.py --iso BFA BGD NER NGA NPL SOM SSD TCD UGA YEM MOZ ETH
```

The coverage run reads 36 chunks (about 1 GB) and takes a few minutes.
